# 架构说明

Repository 与 Service 和 Model 之间的关系是 **依赖倒置** 的，从底层到上层依次是：

```
Model ← Repository ← Service ← Controller
```

让我详细解释每层之间的调用关系：

## 一、层级关系图

```
┌─────────────────────────────────────────────────────────────┐
│                      Controller 层                           │
│         （协调 UI 状态，持有 Service 或 Repository）           │
└─────────────────────────────┬───────────────────────────────┘
                              │ 调用
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                       Service 层（可选）                       │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  • 持有 Repository 实例                              │  │
│    │  • 管理响应式状态（RxList, RxBool 等）               │  │
│    │  • 处理复杂业务逻辑（事务、多步骤操作）               │  │
│    │  • 跨页面状态共享                                    │  │
│    └────────────────────────┬────────────────────────────┘  │
└─────────────────────────────┼───────────────────────────────┘
                              │ 调用
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      Repository 层                           │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  • 持有 Provider/ApiClient 实例                      │  │
│    │  • 数据转换：DTO/JSON → Model                        │  │
│    │  • 数据源决策（缓存/网络）                           │  │
│    │  • 错误处理、重试逻辑                                │  │
│    └────────────────────────┬────────────────────────────┘  │
└─────────────────────────────┼───────────────────────────────┘
                              │ 返回原始数据
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      Provider 层                             │
│                  （ApiClient 原始 HTTP 请求）                 │
└─────────────────────────────────────────────────────────────┘

                              │
                              │ 返回 Model 对象
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                        Model 层                              │
│              （纯数据结构，无业务逻辑）                        │
│              Todo, User, Order 等实体类                       │
└─────────────────────────────────────────────────────────────┘
```

## 二、代码层面的调用关系

### 1. Model（最底层，被依赖）

```dart
// models/todo.dart
// Model 是纯粹的 POJO，不依赖任何其他层

class Todo {
  final String id;
  final String title;
  final bool isDone;
  final DateTime createdAt;

  const Todo({
    required this.id,
    required this.title,
    this.isDone = false,
    required this.createdAt,
  });

  // 序列化方法
  factory Todo.fromJson(Map<String, dynamic> json) => Todo(...);
  Map<String, dynamic> toJson() => {...};
}
```

### 2. Repository（依赖 Model）

```dart
// data/repositories/todo_repository.dart

// Repository 只依赖 Model 和 Provider
class TodoRepository {
  final TodoApiProvider _apiProvider;  // 原始数据源
  final LocalCache _cache;              // 本地缓存

  TodoRepository(this._apiProvider, this._cache);

  // 返回 Model 对象（不是原始 JSON）
  Future<List<Todo>> getTodos() async {
    final response = await _apiProvider.fetchTodos();  // 获取原始数据
    return response.map((json) => Todo.fromJson(json)).toList();  // 转 Model
  }

  Future<Todo> createTodo(String title) async {
    final response = await _apiProvider.create({'title': title});
    return Todo.fromJson(response);  // 返回 Model
  }

  Future<Todo?> getTodoById(String id) async {
    final response = await _apiProvider.fetchById(id);
    return response != null ? Todo.fromJson(response) : null;
  }
}
```

### 3. Service（依赖 Repository 和 Model）

```dart
// services/todo_service.dart

// Service 持有 Repository 实例，管理业务状态和逻辑
class TodoService extends GetxService {
  final TodoRepository _repository;  // 依赖 Repository

  // 持有 Model 作为响应式状态
  final todos = <Todo>[].obs;
  final currentTodo = Rxn<Todo>();
  final isLoading = false.obs;

  TodoService(this._repository);

  // 业务方法：加载列表
  Future<void> loadTodos() async {
    isLoading.value = true;
    try {
      final result = await _repository.getTodos();  // 调用 Repository
      todos.assignAll(result);  // 保存 Model 到状态
    } finally {
      isLoading.value = false;
    }
  }

  // 业务方法：带业务逻辑的创建
  Future<void> createTodoWithValidation(String title) async {
    // 业务验证
    if (title.length < 3) {
      throw Exception('标题至少3个字符');
    }

    // 检查重复（业务规则）
    final exists = todos.any((t) => t.title == title);
    if (exists) {
      throw Exception('该待办已存在');
    }

    // 调用 Repository
    final newTodo = await _repository.createTodo(title);
    
    // 更新本地状态
    todos.add(newTodo);
    
    // 触发其他业务逻辑（如通知、统计）
    _updateStatistics();
  }

  // 业务方法：复杂事务操作
  Future<void> batchUpdate(List<String> ids, bool isDone) async {
    for (final id in ids) {
      final todo = await _repository.getTodoById(id);
      if (todo != null) {
        final updated = Todo(
          id: todo.id,
          title: todo.title,
          isDone: isDone,
          createdAt: todo.createdAt,
        );
        await _repository.updateTodo(updated);
      }
    }
    await loadTodos();  // 刷新列表
  }

  void _updateStatistics() {
    // 其他业务逻辑
  }
}
```

### 4. Controller（依赖 Service 或 Repository）

```dart
// controllers/todo_controller.dart

class TodoController extends GetxController {
  // 简单场景：直接使用 Repository
  final TodoRepository _repository;
  
  // 复杂场景：使用 Service（跨页面共享状态）
  final TodoService _todoService;

  TodoController(this._repository, this._todoService);

  // 从 Service 获取状态（响应式）
  List<Todo> get todos => _todoService.todos;
  bool get isLoading => _todoService.isLoading.value;

  // 页面初始化
  @override
  void onInit() {
    super.onInit();
    _todoService.loadTodos();  // 调用 Service
  }

  // 处理用户操作
  Future<void> onAddTodo(String title) async {
    try {
      await _todoService.createTodoWithValidation(title);  // 调用 Service
```

## 三、依赖注入配置（完整示例）

```dart
// bindings/todo_binding.dart

class TodoBinding extends Bindings {
  @override
  void dependencies() {
    // 1. Provider（最底层，无依赖或依赖 ApiClient）
    Get.lazyPut(() => TodoApiProvider(Get.find<ApiClient>()));

    // 2. Repository（依赖 Provider）
    Get.lazyPut(() => TodoRepository(
      Get.find<TodoApiProvider>(),
      Get.find<LocalCache>(),
    ));

    // 3. Service（依赖 Repository，生命周期与 App 一致）
    Get.lazyPut(() => TodoService(Get.find<TodoRepository>()));

    // 4. Controller（依赖 Service 和/或 Repository）
    Get.put(TodoController(
      Get.find<TodoRepository>(),
      Get.find<TodoService>(),
    ));
  }
}
```

## 四、调用关系总结表

| 调用方向 | 说明 | 示例 |
|---------|------|------|
| **Repository → Model** | Repository 将原始数据转换为 Model | `Todo.fromJson(json)` |
| **Service → Repository** | Service 调用 Repository 获取/保存数据 | `_repository.getTodos()` |
| **Service → Model** | Service 持有 Model 作为状态 | `final todos = <Todo>[].obs` |
| **Controller → Service** | Controller 调用 Service 执行业务 | `_todoService.loadTodos()` |
| **Controller → Repository** | 简单场景可直接调用 Repository | `_repository.getById(id)` |

## 五、什么时候用 Service，什么时候直接用 Repository？

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 简单 CRUD 页面 | Controller → Repository | 减少层级，代码简洁 |
| 需要跨页面共享状态 | Controller → Service | Service 是全局单例 |
| 复杂业务逻辑（验证、事务）| Controller → Service | 业务逻辑集中管理 |
| 需要离线缓存优先 | Controller → Service | Service 管理缓存状态 |
| 多个数据源聚合 | Controller → Service → 多个 Repository | 复杂数据组合 |

## 六、关键原则

```
1. Model 不依赖任何层（纯数据）
2. Repository 只依赖 Model 和 Provider
3. Service 依赖 Repository 和 Model
4. Controller 可以依赖 Service 或 Repository（视复杂度而定）
5. 上层可以调用下层，下层不能调用上层
```

**记住**：Repository 是**数据获取的抽象**，Service 是**业务逻辑的封装**。简单项目可以省掉 Service，但 Repository 建议保留，它是数据层的核心边界。
